Create three backend files that wire together for end-to-end Dockerfile generation:

**1. Hadolint validator** (`backend/app/services/hadolint_validator.py`):
- Create `HadolintValidator` class with `validate(dockerfile_content: str) -> list[HadolintError]` method
- Run hadolint via subprocess with `--format json` flag, reading from stdin with `-` argument per D-14
- Parse JSON output into structured error objects with line, code, message, level fields
- Handle subprocess.TimeoutExpired (30s timeout), json.JSONDecodeError, and FileNotFoundError gracefully
- Return empty list when validation passes (returncode == 0)
- Create `HadolintError` dataclass with line (int), code (str), message (str), level (str)

**2. Dockerfile generator** (`backend/app/services/dockerfile_generator.py`):
- Create `DockerfileGenerator` class with `generate(project_path: str, analysis: dict) -> DockerfileResult` method
- Reuse existing `analyze_repository` from analysis.py per D-01 for project context (language, framework, dependencies, entry points)
- Build structured prompt per D-12 including: project analysis, dependencies, entry points, Docker best practices requirements
- AI prompt must specify per D-22: non-root user, pinned versions, slim variants, multi-stage builds, HEALTHCHECK instruction
- Use existing OpenAI-compatible API pattern from analysis.py (same client initialization with OPENAI_API_KEY/GEMINI_API_KEY env vars per D-11)
- Implement auto-retry on failure per D-13: if generation fails or produces empty result, retry once with simplified prompt
- Return DockerfileResult with dockerfile_content (str), analysis used (dict), model name (str)
- Generate .dockerignore content alongside Dockerfile per D-27 (exclude .git, __pycache__, node_modules, .venv, venv)

**3. Pydantic models** (`backend/app/models/dockerfile.py`):
- `DockerfileGenerateRequest`: project_id (str), optional custom_prompt (str)
- `DockerfileResponse`: dockerfile_content (str), analysis (dict), validation_errors (list[HadolintError]), model_used (str), dockerignore_content (str)
- `HadolintErrorResponse`: line (int), code (str), message (str), level (str)

**4. API router** (`backend/app/api/dockerfiles.py`):
- Create router with prefix `/api/dockerfiles`, tags=["dockerfiles"]
- `POST /generate` endpoint: accepts DockerfileGenerateRequest, requires auth via get_current_user dependency, looks up project from MEMORY_STORE (import from projects.py), calls DockerfileGenerator.generate(), runs HadolintValidator.validate() on result, returns DockerfileResponse with validation errors per D-15
- `POST /validate` endpoint: accepts raw dockerfile_content (str), runs HadolintValidator.validate(), returns list of errors
- `GET /download/{project_id}` endpoint: returns Dockerfile content as plain text with Content-Disposition attachment header
- Register router in backend/app/main.py by importing and including the new router alongside existing projects router

**Hadolint installation**: Include a comment at top of hadolint_validator.py with the Linux installation command: `curl -L https://github.com/hadolint/hadolint/releases/download/v2.12.0/hadolint-Linux-x86_64 -o /usr/local/bin/hadolint && chmod +x /usr/local/bin/hadolint`

**Security per D-22**: All generated Dockerfiles must include:
- Non-root USER instruction
- Pinned base image versions (e.g., python:3.12-slim, not python:latest)
- Slim variant base images per D-23
- Multi-stage builds per D-26
- HEALTHCHECK instruction per D-25
- --no-cache-dir for pip installs
- COPY requirements before COPY source for layer caching
