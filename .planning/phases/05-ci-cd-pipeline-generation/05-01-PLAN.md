- CICDGenerator.__init__: read OPENAI_API_KEY/GEMINI_API_KEY, OPENAI_BASE_URL, OPENAI_MODEL from env (same as DockerfileGenerator)
- generate(analysis, custom_prompt=None) method: builds CI prompt and CD prompt, calls _call_ai for each, retries once with simpler prompt on empty result per D-02, returns CICDResult
- _build_ci_prompt(analysis, custom_prompt, retry=False): generates CI workflow prompt. Include: "Generate a GitHub Actions CI workflow for this project: checkout, setup Python/Node, install deps, lint (ruff), test (pytest), build. Use actions/checkout@v4, actions/setup-python@v5 or actions/setup-node@v4. Standard ML project CI per D-10. Return ONLY the YAML content, no markdown fences."
- _build_cd_prompt(analysis, custom_prompt, retry=False): generates CD workflow prompt. Include: "Generate a GitHub Actions CD workflow: checkout, setup Docker Buildx, login to Docker Hub using secrets DOCKERHUB_USERNAME and DOCKERHUB_TOKEN, build and push Docker image. Use docker/setup-buildx-action@v3, docker/login-action@v3, docker/build-push-action@v5 per D-11. Include a commented-out deploy hook placeholder. Return ONLY the YAML content."
- retry prompts: "Generate a SIMPLE but correct GitHub Actions {CI/CD} workflow for a {language}/{framework} project. Focus on correctness: valid YAML, proper action references. Return ONLY the YAML."
- _call_ai(prompt): same pattern as DockerfileGenerator — openai.OpenAI client, chat.completions.create with temperature=0.3, max_tokens=1500, strip markdown fences. Fallback to _fallback_template on error or missing API key.
- _fallback_template(prompt, workflow_type): return hardcoded CI template (Python: checkout, setup-python@v5, install deps, ruff check, pytest) and CD template (checkout, setup-buildx, docker login, build-push) using current action versions per D-10, D-11, D-12
