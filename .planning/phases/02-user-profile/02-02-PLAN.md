**ProfileEdit component** per D-05 (edit mode), D-10 (inline errors), D-12 (disable save + spinner):

Props: `{ user: User; onSave: () => void; onCancel: () => void }`

State: fullName (initialized from user.user_metadata.full_name), email (initialized from user.email), loading, error, success

Implementation:
1. Form with two fields: Full Name (text input) and Email (email input)
2. Inputs pre-filled with current values from user prop
3. "Save Changes" button: disabled when loading, shows spinner icon when loading
4. "Cancel" button: calls onCancel
5. On submit: call `updateUser({ data: { full_name: fullName } })` for name update
6. Do NOT update email in this implementation — email change requires confirmation flow (research finding). Show a note: "Email changes require confirmation. Contact support to change your email."
7. On success: call onSave (which triggers parent to switch back to view mode)
8. On error: set error state, display in red banner (same pattern as LoginForm)

Use same Tailwind classes as LoginForm for inputs and buttons.

**PasswordChange component** per D-06 (client-side updateUser), D-07 (require current password), D-08 (separate section on same page):

Props: `{ onSuccess: () => void }`

State: currentPassword, newPassword, confirmPassword, loading, error, success

Implementation:
1. Section heading "Change Password" with subtle divider above
2. Three fields: Current Password, New Password, Confirm New Password
3. Client-side validation before API call:
   - All fields required
   - New password must be >= 8 characters (Supabase default minimum)
   - New password must match confirm
4. On submit: call `updateUser({ password: newPassword })` per D-06
5. On success per research finding (password change invalidates session): display success message "Password changed successfully. You will be redirected to login." then redirect to /login after 2 seconds using window.location.href = '/login'
6. On error: display error in red banner
7. Button: "Change Password" with loading spinner, disabled when loading

Important research finding: Password change invalidates current session. The redirect to /login is required because the session becomes invalid after password change.
